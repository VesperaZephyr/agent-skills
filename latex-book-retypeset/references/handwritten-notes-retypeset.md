# 手写笔记重排专项（handwritten-notes-retypeset）

来源：手写笔记《交换代数与同调代数》（这肥肥，926 页扫描 PDF）重排工程。
与"印刷书重排"的差别在于：没有原书 TeX、没有排版基线可对齐、OCR 缺陷类型不同、
编号体系是作者手写的手工编号。随工程进展持续补充。

## 源件与 OCR

| 坑 | 事实与对策 |
|---|---|
| PDF 工具误报加密 | PDF24 合成的扫描 PDF 会被部分解析器（如 Read 工具）报"password-protected"；
  实际 `is_encrypted=False`。换 PyMuPDF 打开即可，不要因此放弃直读原稿。 |
| 手写稿交换图被 OCR 完全压碎 | 交换图识别成散落的行内公式碎片（如 `$ f' \downarrow $ $ f \downarrow f'' \downarrow $`），
  **图的拓扑信息不可恢复**。图的唯一依据是原稿图像：逐图看图重画 tikzcd，
  先列边清单（节点网格 + 每边起止/钩/双头/标签侧别）再写箭头。 |
| 手写 OCR 高频字符级误识 | `0`→`303`；`∑_{i=1}^n`→`\frac{n}{i-1}`；`N ≤_A M` 被拆碎；
  标题行整行丢失或错位（`§5.5`→"§55"、`§14.2`→"§142"、`§9.1` 标题丢失）。
  OCR md 只作检索索引与粗草稿，**转录逐页以图像为准**。 |
| 逐页 JSON 是页级定位器 | PaddleOCR-VL 输出 JSON 为逐页数组（含 block 坐标），可建
  「笔记页码 ↔ OCR 文本」索引脚本，转录前先定位，再渲染对应物理页。 |
| 物理页偏移必须实测 | 扫描件前面常合成了封面/更新日志等非正文页
  （本例：物理页 = 笔记页 + 8）。抽一页已知内容的笔记页实测偏移，
  之后所有渲染按偏移换算；每章开排时复核。 |

## LaTeX 工程

| 坑 | 事实与对策 |
|---|---|
| 自定义环境可选参数必须紧跟环境名 | `\begin{stmt}{定理}{9.2.1}{label}[名字]` 中 `[名字]` 不会被识别为可选参数，
  参数整体左移一格（label 吃到编号、名字悬空）。写法应为
  `\begin{stmt}[名字]{定理}{9.2.1}{label}`。症状：`\newlabel` 键值错位、`\ref` 未定义。 |
| `\theH<counter>` 勿手动定义 | 现代 LaTeX 内核/hyperref 会为 `\newcounter` 的计数器自动维护 `\theH<counter>`；
  手动 `\newcommand{\theHstmtanchor}` 报 already defined。 |
| 手工编号陈述环境的锚点 | `\refstepcounter`（全局唯一计数器）→ `\protected@edef\@currentlabel{手工号}` →
  `\label{...}`：`\ref` 显示手工号且可跳转。章/节号沿用原稿的（如第五章排在第八章后），
  不要让自动编号重排章序。 |
| 手写笔记无页眉，用 plain | 手工 `\notechap` 类标题不设置 `\markboth`，fancy 页眉会残留上一部分（如"目录"）。
  原稿本是手写无页眉，直接 `\pagestyle{plain}`（页脚居中页码）最忠实也最省坑。 |
| Windows 下用 bash heredoc 生成 .tex 会吞反斜杠 | `cat <<'EOF'` 即使引号包裹，经过工具链后 `\\` 可能塌缩成 `\`。
  含反斜杠的 TeX 源码一律用文件写入工具（Write/Edit），生成器脚本走 python 文件而非 heredoc。 |
| 记号统一表前置 | 手写记号存在多义/混用（⨁/⊕、单射钩方向、虚线正合列等）。
  在 cls 注释或专门文件维护「记号 → 宏」映射（如 `\oplus`、`\hookrightarrow`），
  转录时统一用宏，为全书一致性留出唯一修改点。 |
| 原稿陈述编号会跨节延续/重复 | 作者 numbering 不严格：命题 5.0.4 之后下一节直接命题 5.1.5、
  「半命题 5.2.6」、两处都叫例 5.5.1。`check_numbering.py` 报 GAP/重复时**先回原稿核对**：
  是原稿原貌就照抄并记疑点，绝不"修复"编号；重复号的 label 加后缀（ex:5.5.1b）。 |
| 同节两种陈述种类勿共用 label 前缀 | 同节同时有「命题」与「性质」（或「半命题」）时，
  都用 `prop:` 会撞 label（hyperref 重定义警告）。前缀表：性质 `xz:`、半命题 `semiprop:`；
  新种类直接进 stmt 第 2 参即可（种类是自由文本）。 |
| 罗马数字 Ⅰ–Ⅻ 需划入 CJK 字体类 | 原稿「第Ⅰ型/第Ⅱ型」等全角罗马数字落在 Latin Modern 里缺字形。
  cls 加 `\xeCJKDeclareCharClass{CJK}{"2160 -> "216B}`（与 ①–⑳ 的 "2460->"24FF 并列）。 |
| 合并稿 overfull 三式修复（只动版式不动内容） | ① 长等式链改 `align*` 在 `=` 处折行；
  ② 放不下的长行内公式提为独立显示行（句首/句中衔接词保留在正文）；
  ③ 超宽箭头链（相抵/初等变换链）用 `\begin{aligned}` 折行，`\qquad` 尾注单独成行。
  修复后 `build_gates.py` 四闸门必须全 PASS。 |
| 写新 section 前先查遗留草稿 | 会话中断前子代理可能已写出完整 `work/sections/secX.Y.tex` 草稿。
  开工先 `ls work/sections/`：有草稿→逐页对照原稿核校（重点：被"顺手修正"的记号、
  漏掉的衍字/笔误、缺失的 % 疑点注释），修正后采用；无→再转录。盲目重写浪费一倍工时。 |
| 归一段落：`\end{...}` 分支必须先 flush | 把逐句分段的草稿合并成连续段落时，若
  `\end{stmt/proof/note}` 分支不先输出待合并缓冲，环境**末句会被挤到环境之外**
  （编译不报错、纯内容错位）。修复法：`\end` 行后若紧跟非 `\`/`%` 文本行，把该行移回
  `\end` 之前；修完用脚本断言零残留。 |
| 章内节标题与原稿目录可能一字之差 | 页面标题「模的正合序列」vs 目录「模的正合列」、
  「与/和」等。`\notesec` 一律从**原稿目录题**（书签/目录一致性），差异记疑点待作者定夺；
  section 文件自带的 `\notesec` 要改成与骨架一致，否则 dedup_notesec 不去重（题不同）。 |
| 交叉引用单独成遍收编 | 正文「由定理 9.2.1 知」先按裸文本转录（stmt 的 label 早已埋好），
  全书统一跑一遍链接脚本：收集所有 stmt 的 (种类,编号)→label 映射，
  把「种类[空格或~]编号」替换为「种类~\ref{label}」。要点：① 代理可能用「定理~编号」
  裸文本（~ 是普通不断行空格），扫描正则要把 ~ 算作分隔符；② 精确 (种类,编号) 缺失时
  按**编号唯一**回退（原稿「命题 5.2.6」实指半命题 5.2.6）；③ 未转录章的引用留裸文本
  逐章重跑收编；④ 验证用 PDF 链接注释：源页引文里的编号必须出现在目标页文本中。 |

## 手写正斜体与宏层（作者反馈沉淀）

| 坑 | 事实与对策 |
|---|---|
| 手写正体斜体不分 | 作者手写不区分 \mathrm/\mathcal/\mathsf，重排时按**标准排印惯例还原**：
  算子名/范畴名正体、变量斜体、花体字形（宇宙 𝒰、指标范畴）用 \mathcal/\mathscr、
  哥特体（理想 \mathfrak{p}）按原稿字形判断。 |
| 记号全部宏化，勿堆 \operatorname | cls 里建宏表（\Ob \Mor \Hom \id \coker …；范畴名 \Set \Grp \Top …），
  章节源码一律用宏；新记号需求先进宏表（唯一修改点）再进正文。
  否则后统一替换代价大且易漏。 |
| [注]/[约定] 独立环境 | 手写稿高频出现「[注]：」「[约定]：」段落，定义 `note` 环境
  （可选参数承载变体：`\begin{note}[约定]`），不要用裸段落硬排。 |
| 手工编号陈述环境签名 | 可选参数（陈述名字）必须紧跟环境名：
  `\begin{stmt}[米田引理]{定理}{6.5.1}{thm:6.5.1}`。
  症状（签名写反时）：`\newlabel` 键错位、`\ref` 未定义。 |
| 编号连续性自检 | 原稿按（节,种类）分计数器（定义 X.n.1..N 与定理 X.n.1..N 各自连续）。
  写脚本提取全部 `\begin{stmt}{种类}{X.Y.Z}` 断言每序列 1..N 连续，
  能立刻暴露漏转录的陈述——比逐页数快且可靠。 |
| 子代理并行转录模式 | 按节/章切片并行：每代理只写自己的 `work/sections/secX.Y.tex`
  （含 \notesec 行）+ 在 `work/test/` 用 cls 副本自检编译；
  主会话串行合并（注意代理文件自带的 \notesec 行会与骨架行重复，需按节号去重）、
  统一疑点编号（代理前缀 F1→S31 式重命名）、编译跑门槛。
  合并是纯机械步骤，转录的图像判断留在代理，判断一致性靠统一的约定提示词。 |
| 子代理提示词必备条目 | ①物理页=笔记页+偏移 与放大裁剪代码模板；②边界规则（节起止标题）；
  ③忠实性红线（照抄笔误+疑点占位符协议）；④LaTeX 约定全表（stmt/note/宏列表/tikzcd 配方）；
  ⑤已知坑（tikzcd 标签逗号 `{,}` 保护、箭头射入空单元格报错改三列汇聚式）；
  ⑥自检编译 + 编号连续性自检；⑦报告格式（陈述/图/疑点/新宏/编译/记号观察）。 |
| tikzcd 手写图配方 | 自然变换 2-胞：`\ar[r, bend left=50, "F"] \ar[r, bend right=50, "G"']
  \ar[r, phantom, "\Downarrow\theta"]`；标签含逗号用 `{,}` 保护；
  多步位移 rr/dd；虚线唯一态射 `\ar[d, dashed, "\exists!"]`；
  箭头射入空单元格会报错，改三列汇聚式布局。 |
| 并发限额 | 平台对子代理有并发上限（实测约 2）。超限报
  "model/user concurrency limit exceeded"（瞬时失败）或
  "Subagent was inactive for 600000ms"（排队卡死）。
  一次最多并行 2 个代理；卡死后检查产物目录再单发重试。
  额度耗尽时（"exceed quota limit"）改为主会话自己转录，不必等待。 |
| 范畴名统一 \mathsf | 手写不分字体，但现代范畴论排印惯例是**范畴名用无衬线体**：
  `\Set \Grp \Top \Ab \Vect \Cat \PreOrd \Disc \Mod \Ring \CRing \PCTop \Alg \Fct \Rep`
  全部定义为 `\mathsf{...}`；算子名（\Hom \Ob \Mor \Spec …）保持正体。
  验收：PDF 页字体表里应出现 LMSans/CMSans 族（`pymupdf page.get_fonts()`）。 |
| 裸范畴名是缺陷 | 宏层建立前写的正文常留 `$Set$`、`$Vect(k)$`、`\to Set$`、
  `$Mod\mbox{-}R$` 等裸名（会排成斜体）。用状态机脚本按 `$`/`\[` 切换数学模式、
  只在数学段内把裸名替换成宏（`scripts/migrate_bare_names.py`），
  并用 `scripts/scan_bare_names.py` 断言 0 残留。 |
| 原稿省略标点，重排必须补 | 手写体常无句末标点、分句无逗号。转录时按体例补「，」「。」「：」，
  引入列表/公式的句子末尾补「：」；只补标点，不改措辞。 |
| 原稿硬换行一律丢弃 | 手写每写满一行就换行，与语义无关。重排时把同一段话合并成连续段落，
  只在原稿真实分段处断段；不要把原稿行末当成句末（常导致把半句当整句加句号）。 |
| 显示式末尾标点必须 ASCII | 全角「，」「。」写进 `\[...\]`/`align*` 内（如 `=l，\]`）会报
  Missing character U+FF0C（xeCJK 不覆盖数学模式，落到 lmroman）。文本段补标点没约束，
  但显示式/align 行尾一律用 ASCII `,` `.`。定位法：测试文件加 `\tracinglostchars=3`
  再 `xelatex -file-line-error`，Missing character 升级为带源码行号的错误；
  修复合并稿用脚本按「行尾全角标点 + 次行 `\]`/`\end{align*}`」模式替换并断言清零。 |
| tikzcd 标签内 & 活性化 | 标签里的 `&` 即使裹进引号标签（`"\begin{pmatrix}a&b\end{pmatrix}"`）
  仍在标签排版时被 pgfkeys 活性化报错；tikzcd 内的 2×2 矩阵标签用 `\genfrac(){0pt}{}{…}{…}`
  等无 & 构造（amsmath 自带），列向量用 `\binom`。 |
| 代理死亡先验尸再重发 | 长批代理（≥36 页 / >2h）可能 "Model request timed out" 猝死。
  先查产物：若 section 文件以「综上…得证.\end{proof}」式完整结尾且 OCR 末段吻合，
  很可能只缺自检——主会话补跑 check_numbering + 试编译 + 修 overfull 即可收编，
  不必重转录（§15.6 先例：代理死于收尾，正文 96KB 完整）。 |
| 目视核对未做的批次要补图审 | 转录代理若死于「画完逐边核对」之前，其图的保真未经目视验收；
  合并后按 latex-array-diagram-audit 流程派 fresh-context 图审代理
  （渲染成书页 vs 原稿页并排、放大钩端/双头/虚实线、边清单不得代替原图），修复后重跑闸门。 |
