# 数学 PDF 书签

根据原书目录建立完整、清晰的书签，使每条书签落在对应标题行。先检查现状，选择适合该书的方法；书签存在或自动体检通过都不等于正确。

## 先判断怎么做

1. 对文件夹先清点 PDF，用 `references/bm_quality.py` 找出空书签、页顶、乱码、稀疏、层级异常和非单调等候选问题。结果仅用于安排核查优先级；`needs-review` 不是通过或可跳过的结论。书签稀疏、相同纵坐标和编号层级冲突也可能误报，`nonmono` / `top` / `oor` **同样不能单独定罪**：它们必须优先核查，不得用"坐标口径不同"一句话解释掉，也不得直接当成错误去改（见精度规则硬规则 24）。裁决时记录涉及的条目、目录顺序、实际落点与依据；确认是原书合理的非单调编排就保留并写明理由，确认落点或顺序错才修。每本都须对照印刷目录并检查正文标题落点，才能决定跳过或修订。不得以页码标签存在或不存在判断书签质量，也不得据此擅自修改标签。
2. 查看印刷目录、现有书签、正文文字层及页码标签。优先识别并保护质量可靠的现有书签（包括原生及后期制作）：对照印刷目录的覆盖、顺序和层级，抽查书前、各章、不同层级、习题和附录的实际跳转；完整可信且用户未要求修复时就跳过，不重建或规范化。目录链接和命名目标可提供线索，但不是必要条件。元数据、命名目标或书签数量单独都不能证明质量；有缺漏、异常或用户要求修复时继续核查。记录物理页与印刷页的对应关系；扫描缺页可能使偏移分段变化。
3. 选择路线：
   - **文字层部分可用或标题漏读**：从印刷目录建立条目，对缺失或位置可疑的标题渲染原页并做 PDF 外 OCR；以原页图像判定，不因正文文字层有内容就视为标题可读，也不把页眉或误读当作目录页码错误。
   - **正文文字层可靠，目录可读**：按页缓存文字和位置，建立目录条目表，在候选正文页定位。旧树可提供线索，须逐项核对。可先尝试 `references/heading_scan.py`；其门槛不通过就改用目录转录和定位。
   - **目录完整、旧树结构可信但落点不准**：保留经核对的结构，逐条重定位；参见 `references/reanchor.py`。
   - **旧树缺项、层级或标题有误**：以印刷目录重建。扫描本 OCR 不可靠时目视转录目录，文字层只作定位线索。
   - **纯扫描、无文字层**：只对需要的目录页和目标页渲染/OCR；先读 [扫描目录与定位](references/scanned-bookmark-guide.md)。用户未要求修改正文文字层时，使用 PDF 外的 OCR 证据。OCR 时用 `winocr.ps1 -Dpi` 把渲染 dpi 写进 dump 头，按书选 `-LangCode`，需要行内单词坐标（页眉页码、目录列）时加 `-Words` 交给 `ocr_rows.py` 重组。

## 页码标签（书签任务常规核对）

为新处理书签的书常规核对阅读器页码标签；缺失或与原书不符时同步建立或修正，可靠的现有标签应保留，用户另有要求时依用户要求处理。对照原书实页确认各编号段，包括书前重复编号与无印刷页码的页面；页码标签是阅读器导航信息，不改变页面内容或物理页数。检查实际印刷页码并在分段边界及前、中、后核对；无文字层时渲染页码并人工核查，缺页可能改变偏移。区分自动推算与原页证据，不确定处注明。多组重复罗马数字需明确区分，避免页码输入产生歧义；用户偏好优先。操作前后保护书签及其原始落点，并按备份、候选和写后验证步骤核验。候选副本可使用 `references/page_labels_candidate.py`，输入必须是经原书核对的分段方案；它不负责识别印刷页码、不写回原件。具体用法与验收边界见 [页码标签核对](references/page-label-guide.md)。

## 子代理协作

在支持并允许子代理的环境中，批量处理或复杂单书可按需并行；任务较小或无法使用子代理时由主任务独立完成，不降低核验标准。不同书优先按书分工；单本书可分别委派印刷目录与结构核对、正文目标及页码分段核查、候选结果的独立验收。明确每个子代理的文件、页段、任务范围和独立产物位置，避免同时写同一文件；让核验者依据原书证据独立判断，不把候选结论当作事实；可将目录转录的逐项核对与最终读回落点的逐图核对分开委派，记录各自实际覆盖范围。

子代理报告应包含文件、实际检查范围、目录与书签差异、抽查目标和证据位置、未核实事项；区分自动结果和目视核验。主任务负责合并结果、解决冲突，判断是否保留或重建，并完成整体验收。各代理不得并发写回同一 PDF；由主任务在验收后按本技能的备份与写回步骤统一处理。用户指定审查范围和修复要求优先。

## 执行与验收

1. 整理目录白名单：保留原书标题、编号、顺序和层级，记录印刷页码。另检查目录之前的序、前言、译者序等书前内容以及目录页本身，即使它们未列入印刷目录也要补上；正文项目以目录为准。如目录只列一级，则按其结构处理。旧书签不是权威来源。双语或合订本先辨认各语言或分册的独立目录、正文范围和页码段，分别核对覆盖，另检查目录未列出的补遗等内容。
2. 根据印刷页码、实测 folio 和已有页码标签找候选物理页；以正文标题确认目标。目录页码可能印错，逐条核实并记录例外。扫描件可能缺叶，使 `物理页 - 印刷页` 分段变化：批量任务先扫描全书页眉/页脚 folio 定出分段，再逐条定位；缺页导致标题页不存在时，落点写该节现存首页并在汇报中注明。排除同名页眉、正文引用及目录页。批量任务应缓存页面文字和坐标，避免每条重复扫描整本书。
3. 目标坐标落在标题上沿或紧上方，使完整标题和编号可见。`set_toc` 的页码为 1-based；目标坐标不能跨书套用固定偏移。**落点参数（数字 `y` 或 `to.y`）的语义一律是「距页顶磅数」，工具内部自己会翻成 PDF 原生坐标，绝不要再按页高减一次**；dict 形式须写全 `{'kind': LINK_GOTO, 'to': Point(x, y), 'zoom': 0.0}`，漏 `kind` 会让目标丢失。用两个不同输入探针标定 `landing = k*input + b`，断言 `|k|≈1`，反算写入值（探针只消除"写入时再翻一次"这类口径错误，不消除探针位置测错或计划本身错）；目标页 `rotation≠0` 时该标定退化（实测 `k=0`），**不要硬换公式，直接拒绝处理这些页并单列汇报**。⚠️ **`get_toc` 回读的 `to.y` 恒等于你传入的值，拿它断言"误差 <0.05 pt"是循环验证，任何口径错误都会返回 0.0001 pt**——落点必须用 `references/landing_audit.py` 从原始 `/XYZ` 反算（`view_top = crop.y1 − top`）并与计划值比对。**并且要分清两问**：这一项只证明"写入 = 计划"，不证明"计划压对了标题"；后者的证据只能是落点下方的文字层比对或逐格拼版目视，工具末尾的覆盖范围（`口径可反算 x/n`、`目标自动可验 y/n`、`目标需目视`）必须原样写进汇报。**扫描件不得报"自动验证通过"**（自动证据 0/n）；做完逐格拼版人工验收后，可报"人工验收通过（自动证据 0/n）"，两者不得合并成一句"已验证"。具体陷阱见 [精度规则](references/detailed-rules.md) 硬规则 20、23、26。
4. 在候选副本逐条核对标题、层级、页码和落点。先依据每个目标页的页面尺寸和版心设置 `references/ink_audit.py` 的 `--x0`、`--x1`、`--tilex1`，使用 `--every 1` 检查墨迹；工具会拒绝越出页面的窗口。**人工查看覆盖全部条目的拼版，确认完整标题和编号可见**；巨幅页面可用 `--tileheight` 增高条带，仍看不清时另看原页。拼版由 `landing_audit.py --sheet` 生成，红线从 PDF 原始 `/XYZ` 反算，不得拿规划阶段 JSON 的 `y` 画线——那只是在验证自己的中间文件。**有文字层时可先用 `landing_audit.py` 的编号/标题文字比对缩小范围，但它只是补充证据，不能替代拼版**：它只能说明"落点下方文字与标题相符"，不能说明排版上恰好压在标题上沿，扫描件更是 0 条可验。墨迹通过不代表命中的是标题；未通过也可能是正确落点与检测间距不符，需结合图像说明。修改目标后重新读回并复查受影响条目；若批量调整坐标，重新验收全量落点。对于缺页、定位失败或目录/正文不一致的条目，记录证据，不猜测落点。
5. 写回原件前确认原件自核查以来未变化，建立字节一致的备份并验证，避免覆盖既有备份；写后重开核对书签、落点、页数、页面几何及内容、元数据和页码标签。**写回后的验收用 `references/verify_writeback.py --new 写回后.pdf --orig 备份.pdf --items 条目.json --sheet 拼版目录 [--manual-review 验收记录.json]` 一次跑完**：它依次做内容完整性比对与落点审计，**把"自动化检查"与"人工验收"当两层证据分别汇总**，结论只有四种：
- `FAIL`（硬失败）；
- `INCOMPLETE`（缺 `--orig` / `--items`，或有读取失败项——自动层自己就没覆盖全）；
- `AUTO-PASS`（自动层完整通过，但人工验收未记录）；
- `PASS`（自动层通过 **且** `--manual-review` 记录覆盖全部条目）。

所以**不给 `--orig` / `--items` 永远不会 PASS**，文字层命中也不升级为 PASS——它只是补充证据。`--manual-review` 是一份 JSON：`{"reviewed": 553, "total": 553, "sheets": 18, "method": "逐格拼版目视", "by": "...", "date": "..."}`，`reviewed` 不足或 `method` 缺失按"未完成/记录无效"处理。两个子项也可以单独跑：落点用 `landing_audit.py`（原始 `/XYZ` 口径），**"正文无损"用 `pdf_integrity.py`**——它逐页比几何、内容流（原始+解码）、文字层、逐词坐标、图像、字体、矢量、链接（含网址/目标页/命名目标）、注释、控件（含字段值），分为 `CONTENT_DIFF`（硬失败）、`RECOMPRESSED`（字节变而解码一致）、`UNVERIFIED`（某 facet 读取失败，退出码 2，**不许当作"两侧都空=相等"**）。它的覆盖仍是"能读到的 facet"：不比对控件外观流与 JavaScript 动作，也不枚举 launch/remote 等动作，通过只能表述为"逐页 facet 比对未见差异"，不能表述为"所有内容与交互均无损"。只比图像流 md5 不足以证明正文无损——文字层、矢量、字体都可能被动而图像全等；**不要拿 xref 编号当比较键**，重写后必变，会报出"每页都有差异"的假警报。已有标签先核实，除非任务要求或明确有误，不要随意重写。失败时恢复备份。候选副本通过不等于原件已写回。
6. 汇报已处理文件、书签数量与层级、修正或无法定位的项目、验收结果及备份位置；标明候选与已写回状态。**验收结果必须分两行写**：自动化检查（内容完整性、`Q1 口径 x/n`、`Q2 文字层证据 y/n`，含 `UNVERIFIED` 项）与人工验收（逐格拼版 n/n、方法、日期）；只有两层都成立才可写"已验收"，否则按 `AUTO-PASS`/`INCOMPLETE` 如实表述。不要将自动检测结果表述为人工已确认。若用户指定了交接文档，按要求记录完成状态与未解决事项。
