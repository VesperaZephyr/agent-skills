# 页码标签核对与修正

新处理书签时常规核对页码标签，缺失或与实页不符时建立或修正；可靠的现有标签予以保留，用户另有要求时从其要求。先记录原 PDF 哈希、书签树及落点、页数、元数据和已有 PageLabels。根据实页印刷页码建立物理页与编号段对应表：章首或目录首页可能没有印出页码；前言、总序、目录可以各自从 i 重启，不能合并为连续的一组；缺页可能使正文偏移发生变化。无印刷编号的封面或版权页用清晰的独立标签，不将推算的页码冒充印刷页码。多组相同罗马数字可用不同前缀区分，其中最常用的目录页可保持裸罗马数字；前缀应与阅读器兼容并向用户说明。

## 可复用的候选生成工具

先根据原书核实方案，保存为 UTF-8 JSON 数组；`page` 是从 1 开始的物理页，`start` 是该段的起始编号。无 `style` 的前缀段只适用于单页；前缀目前限定可打印 ASCII，以避免已发现的编码问题。编号样式为 `D`、`r`、`R`、`a`、`A`。下面仅为格式示例，不能套用于其他书：

```json
[
  {"page": 1, "prefix": "Cover"},
  {"page": 2, "prefix": "Preface-", "style": "r", "start": 1},
  {"page": 5, "style": "r", "start": 1},
  {"page": 8, "style": "D", "start": 1}
]
```

```powershell
python references/page_labels_candidate.py "原书.pdf" "分段方案.json" "候选.pdf" --report "页码报告.json"
```

工具只创建新候选和报告，不覆盖现有输出、不写回原件；拒绝未覆盖第一页、分段无序、重复标签、不可用前缀等方案。它重开候选，逐页比较实际标签与方案，比较书签及落点、逐页内容和文档信息；报告记录全部标签及原件哈希。它不能判断方案是否符合印刷原页，也不能代替独立视觉核验和后续备份写回。页面完整性比较仍以 `pdf_integrity.py` 可读取的范围为限。

在候选副本上使用 PageLabels（例如 PyMuPDF `set_page_labels`），每段 `startpage` 是从 0 开始的物理页索引；`style` 的 `r`、`R`、`D`、`a`、`A` 分别表示小写/大写罗马数字、十进制及小写/大写字母；指定 `firstpagenum`。从物理第一页建立有效标签，避免产生无法解析的前置页。非 ASCII 前缀的实际序列化在不同库/阅读器中可能出错：必须在写后重开并逐页读回，同时在可用阅读器检查显示；若不能正确显示，改用可确认兼容的短前缀并说明。不要假定所有阅读器都以同一种方式解析重复标签或前缀。

验证所有页的标签唯一性、预期编号、分段起止；与原图可见的页码和无页码章首页相互印证，记录抽样及不可辨认范围。检查现有书签完整树、物理页和目标坐标保持不变；检查页面几何、内容流、文字、图片、元数据和页数。`pdf_integrity.py` 会把预期的 PageLabels 差异报告为失败，因此应逐项核实其余所有差异，而不是直接把结果当作无损通过。最后确认原件未变化、创建并验证字节一致备份，写回后重开复验标签、书签及内容。

## 例：王晓光《复变函数》

2026-11-19 所核验版本共 405 个物理页：物理页 4–5 总序 i–ii，7–8 前言 i–ii，9–16 目录 i–viii；17–401 对应正文及参考文献印刷 1–385。物理页 1–3、6 及 402–405 为无印刷编号的书前、书末页。旧标签从物理页 2 才开始，且目录和正文均晚一页。以 `Series-`、`Preface-` 区分重复罗马数字，目录保留 i–viii，正文保留阿拉伯数字；其他无编号页面用英文描述。原页眉图逐段检查用于判断，章首和参考文献首页无可见页码时由目录和邻页佐证；以上对应关系只适用于这个 PDF，其他版本须重新核对。
