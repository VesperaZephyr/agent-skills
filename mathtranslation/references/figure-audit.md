# 全书插图对账审校（figure audit）

当任务是对已完成译稿做"原书 ↔ 译稿"的**全书逐幅插图对账**（而非单幅修复）时，
按本规程执行。它补全 [illustrations.md](illustrations.md)（六问诊断与选型）与
[figure-capture.md](figure-capture.md)（裁切/重绘实操）未覆盖的流水线：
双向清单 → 整页对照渲染 → 分章派工 → 协调者源码级复核 → 脚本化修复 → 重渲染逐幅验证。
2026-10 于 GTM 304（34 幅：3 截图 + 31 TikZ）实战校准。

## 0. 先验证"原书"身份（GTM 304 教训）

渲染前核实手头"原书 PDF"真是原书：抽取若干页文本看语言、搜题注模式
（英文书必有 `Figure x.y`，命中 0 即可疑）、页数与书目记录比对、文件大小量级。
本项目项目目录内一份 307 页旧中文构建冒名原书（真原书 379 页在别处），
若未发现，全部对账会拿译稿旧版当基准。权威源路径写进交接文档，冒名文件建议改名。

## 1. 双向清单，按身份对账

- **译稿侧**：解析 TeX 链的 figure 环境（asset/\includegraphics/\input、caption、label、宽度）
  ＋ 扫描 figs/ 中未被引用的遗留资产（本例约 20 个早期方案 PNG，列入职守清理）。
- **原书侧**：题注清单取自 OCR markdown 与源 PDF 文本搜索两路互证；记录页数。
- 数量一致只是初筛：逐幅按身份（内容、面板、标注）对账，编号映射写成 manifest。

## 2. 第一遍用整页并排对照，不要用题注锚定裁剪

- 教训重演：按 caption 定位"上方图形区"的裁剪法会被正文数学式的分数线/根号
  （get_drawings 把它们当绘图）污染，裁出文字带。**首遍渲染整页并排对照图**
  （左原书页、右译稿页，约 110dpi）：身份/完整性/裁剪/版面四问在此层解决，
  有疑问的图再进入第 3 步放大。
- 题注页定位：两侧各搜题注 needle；正文引用与题注同串，用**页面图形覆盖率**
  择优（题注页必有大图形）。中文题注用冒号形式（`图5.1:`）区别于 `(见图5.1.)`；
  注意 CJK 拼写变体（`图5.1` 可能无空格）。manifest 里的页码映射要复核——
  本例 10.2/10.3 的映射曾排错序，审校员据 manifest 复核时纠正。

## 3. 放大协议

凡有疑问（箭头头方向、阴影区域、标签重叠、曲线渐近）必须放大复核，
不得凭整页下结论：按整页对照图目测图形带的上下比例，clip 渲染 200dpi
（必要时更高），上下拼接存证后 Read。两类高信号检查：
- **标签叠印**：高 dpi 下逐一读标注（`T^*_zM` 与 `Char(P')` 曾叠成乱码）；
- **z-order 填充**：像素采样灰度值——本应两层的区域只测得一种灰度 = 后画的
  浅色把先画的深色盖掉（交换两处 fill 顺序即修）。

## 4. 分章派工（全新上下文），带校准样例

- 按体积分组（单 agent ≤ 约 10 幅或 170KB），**并发 ≤ 3**，超限分批重发。
- 任务书必备：对照图路径 + 页码映射、放大配方、六问表、**校准样例**
  （一道"通过"与一道带证据的 P2，对齐判级尺度）、已知问题排除清单、
  "每条缺陷必须给出 tikz 源码行号"的要求、图注逐字核对义务。

## 5. 高发缺陷类（审校员按此排查）

1. **流/法向箭头反向或两板互换**（最常见 P1）：先按数学定方向——源发射、汇吸收；
   再对照原书放大件。TikZ 里箭头方向是确定性的：`(a)--(b)` 的头在 b。
2. **z-order 填充覆盖**（见第 3 步）。
3. **自创表示与标注/图注自相矛盾**（C_∞ 画成有限带却称锥；径向集画成与 S*M 相切
   使"内部法向源"失去载体）。
4. **两个对象被合并且标签互相矛盾**（同一锥面左标 |X|=2τ 右标 H̄⁺）。
5. **原书锚点元素缺失**：着色支集方块、共变体标签、位移双箭头、第二支曲线、
   围道方向箭头、外圈轮廓。
6. **记号损坏**（Ω_{δ_I=η_I}）：图内标签与图注同源损坏，且破坏与正文的记号一致——
   修图必须连同正文 grep 同款记号。
7. **图注忠实度**：意译扩写/改写/压缩都要标注；重画后检查图注是否残留描述旧设计的
   尾句（"以一条分离曲线示意"）。
8. 彩色→黑白：可接受，前提是区分职能已由文字标签补偿；否则要求上色。

## 6. 协调者复核与脚本化修复

- agent 的每条高影响结论，协调者**先在 TikZ 源码中复核**再采信——箭头方向、
  线型（实/虚）、坐标在代码里是确定性的，复核成本低（本例 7 项 P1 全部
  源码证实，且发现 agent 一处页码映射错误）。
- 修复脚本持久化到 `_tools/`，整宏替换用**索引切块**（`\newcommand{name}{%`
  到其后第一个 `\end{tikzpicture}%`），不要用跨行精确串；
  行级插入/换序用 splitlines(keepends=True) 兼容 CRLF。
- **工具陷阱**：绝不用 shell heredoc 写含反斜杠的补丁——heredoc 会吞一层反斜杠，
  `\f` 变 formfeed 静默失配（无效转义如 `\d` 反而幸存，更具迷惑性）。
  补丁一律写成 .py 文件执行。
- 修复后闭环：重建（0 错误 / 0 未定义引用）→ **重渲染受影响的对照图 →
  逐幅目检**。编译通过不是验证；还要重看图。

## 7. 记录与移交

交接文档新增一节：已修复表（图号/内容/级别/验证状态）、未修复 P2/P3 遗留清单
（下次审校候选）、流程发现（冒名源 PDF、遗留资产）。对照图与放大证据目录、
清单与渲染脚本路径一并登记。

## 8. 校准数据（GTM 304 回归基准）

34 幅；3 截图 + 31 TikZ；发现 7 项 P1（其中 5 项是流箭头类）、约 15 项 P2、
若干 P3；修复 10 幅并逐幅重渲染验证；3 个审校 agent（2+1 分批），
单 agent 最高 ~9.6M token（10 幅深度对账的量级参考）。
