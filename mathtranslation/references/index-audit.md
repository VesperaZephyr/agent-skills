# 数学译著索引审阅与安全修复

适用于全面索引审阅、术语改动后的关联索引复核，以及章首占位索引污染。
与 [terminology-review.md](terminology-review.md) 配合使用。这里的检查维度相互独立：
词头没有重复，不能证明原书条目齐全；链接存在，不能证明落点语义正确。

## 1. 先建范围和处置清单

- 从实际编译入口收集正文、前言、附录和索引宏；分别登记主索引、符号索引。
- 对照指定版次的原书索引建立清单：完整父子路径、原书印刷页码及物理页、
  目标正文、译稿标记位置、处理理由、最终显示页码和链接核验状态。
- 原书分栏索引的缩进和跨页续项决定层级。提取文本保留栏坐标，必要时看页图；
  不能把 PDF 阅读顺序或 OCR 的相邻行直接当成父子关系。
- 分开统计“已审阅、已修复、最终 PDF 已验证、待核”。只给出主索引或符号索引
  的总条数，不能据此声称全面审阅完成。
- 原书索引页先产生候选；只有桥接到原书正文语境、译文源码标记及当前 `.idx`、
  `.ind` 和 PDF 目标后，才能判为漏项或错项。每批记录所据的源 PDF 与冻结译稿
  哈希。重新排版后更新页码映射和链接证据；旧批次的语义结论只在相关源文与
  TeX 内容未变时沿用。

## 2. 同时审排序键、显示词头和层级

对 `\index{sort@显示词!childsort@子项}` 的每一级分别审计：

1. 从源码及 `.idx` 收集完整路径、排序键、显示词、释义和源位置。花括号须配对；
   注意 makeindex 的引号转义、数学内容及自定义索引宏，不能用 `[^}]*` 解析所有条目。
2. 同一显示路径若使用不同排序键，列为合并候选；检查拼音漏字、连字符、
   空格与大小写。例如 `hecheng-yinzi/hechengyinzi`、`yuj/yuji`、
   `Noetherhuan/noetherhuan` 能让同一显示词头分裂。
3. 同一排序路径若带有不同显示词或不同释义，也列为候选；不能为清零重复而
   把不同义项强行合并。英文相同的 `simple` 可指群、模、双复形或单态射用语，
   必须看上下文及原书索引安排。
4. 重建后再扫描 `.ind` 的一级词头和各父路径下的同级子项。源码改了一部分键，
   仍可能残留另一个旧键；逐层去重，不能仅扫描一级 `\item`。
   自动比较只生成候选；`.ind` 可能有多行条目、TeX 命令和不带页码的父项。

原书的“父项—子项—孙项”是检索关系，不是词语邻近关系。例如：

- `order` 可按群、元素、幂级数分子项；缺少幂级数的阶应补到定义它的习题处。
- `simple` 的群、模、双复形等子项和“60 阶”的更细层级按原书缩进决定，
  不能因它们同页出现就随意升降级。
- 人物 `Noether, Emmy` 与性质 `Noetherian` 分开；“Noether 条件”应归性质，
  不应借用人物词头。派生定理名是否独立，按原书和项目索引体例处理。
- 保留有意义的双向检索入口（如 `ring!Noetherian` 与 `Noetherian!ring`）；
  不要将它们误判为同一父路径下的重复。

项目采用的术语必须同步进入正文、索引显示词、派生子项和术语表。
例如用户选定 `universal property = 泛性质` 后，应搜新旧中文、英文概念和
积/余积等关联父项；这是一项项目术语决定，不能据此替换其他义项的“万有”。

### 未分组区必须单独检查

一级词头去重通过后，还要检查 `.ind` 中 `lettergroupDefault` 及 PDF 索引开头。
裸中文排序键、Unicode 希腊字母开头的键可能进入默认组；它们不会被重复扫描发现。
为应按拼音分组的词补充明确 Latin 排序键，如 `linghuazi@零化子(annihilator)`；
δ 函子可用 `delta hanzi` 排序并保留显示数学符号。优先合并项目已有规范词头。
检查主索引与符号索引各自的默认组，逐条说明有意保留的非字母组，不机械清空。
重建后查看索引首页，确认默认区只含有意保留项；这应成为独立验收项。

## 3. 页码污染与符号索引

- 一大批无关索引集中指向同一章首页，且标记堆在章首，提示可能是占位索引。
  按条目找实际定义或有效讨论并迁移；只有核实无依据的条目才移除，不能整批猜删。
- 将原书符号索引与译稿符号索引分别比对。主索引覆盖检查不能替代符号覆盖检查。
- 区分容易混淆的大小写、字体、上下标及相似宏，如 `tr/Tr`、`Tor` 与
  `Tor_i`、`R_p` 与 `R_\mathfrak p`；PDF 文字提取可能丢掉这些区别。
- 排序键和排印标签分开：符号缺少排序键可能进入未分组区；不能凭显示顺序推断
  数学含义或删除“看起来重复”的符号。按该书索引体例选择稳定排序键。
- 标记尽量附在对象的定义或实质讨论处，避免留在章首或可能跨页的前置段落。
  若对象不存在于译稿，先核查是否正文遗漏，不能只补一个索引标记。

## 4. 批量修改：先全部预检，再写入

- 将操作记录为 `(文件, 精确旧串, 新串, 预期次数)`；预期不符时先停止该批写入，
  核实是旧版本、重复执行、漏项还是误抄。全批预检通过后才执行。
- 不要用跨章非贪婪通配正则删除“占位区”，如从某标记匹配到下一个空行。
  空行、注释及行尾差异可让匹配吞掉章内大段正文。已知标记块应按行边界、
  配对括号、明确结束标记和预期相邻条目数解析；越界即退出。
- 保留编码、BOM 状态和换行。改动前备份到唯一批次目录，记录原文件摘要；
  输出先写临时文件，经检查后替换原文件，避免直接截断写入。
- 对结构删除或迁移，除匹配次数外还检查非索引正文差异、章节标题、环境/标签
  与文件长度变化。大量字节或正文消失应立即停下；尺寸相同也不证明正文相同。
- 幂等脚本须明确识别“已应用”；一次性脚本重跑遇到旧串缺失应退出。
  不允许靠忽略告警来重放整轮旧修改。

## 5. 遇到损坏时的恢复闭环

先停用有问题的变换，保存受损版本和日志。逐文件选择经过内容核验的完整备份，
不能按“最新备份目录”整批覆盖，也不能只以文件大小相同判断版本相同。
按操作清单核对备份之后的修改，仅重放确认缺失且前置条件满足的操作；
记录已恢复、已重放和仍待核项。恢复后重做正文完整性、术语残留、索引和构建检查。
不要把“编译成功”当作全文未丢失的证明。

## 6. 分批闭合，减少反复重建

先形成一批有证据的修复计划，审完相关父子项、同义词头和拼音变体，再修改与预检；
一个完整批次执行一次全构建。只有新增修改、构建失败或尚未解决的疑点需要再次构建。
持续记录本轮修订清单与待核清单，恢复工作时从清单继续，避免反复扫描已完成项。

索引必须由稳定页码生成。若流程先在第一遍排版后运行 splitindex/texindy，再执行
多遍 xelatex，最后正文页码可能变化，而 PDF 仍读着第一遍的旧 `.ind`。
最终排版后保存合并 `.idx`，重新拆分/修键/排序，再编译；比较此次前后合并 `.idx`
（含索引种类、完整条目与页码）是否一致。设有上限的收敛循环，不一致继续刷新，
达到上限即报告失败；不能只比较条目数量或索引首末页。验证用的快照与参与排序
的索引输入应来自同一轮，不以过时的拆分 `.idx` 自证。Aluffi 实战中此缺陷使
不变因子索引落在定义前一页，只有解析链接并阅读目标页才暴露。

全构建后依次核对：源码标记 → `.idx` → `.ind` → PDF 可见条目 → 实际链接落点。
印刷页码和 PDF 物理页可能存在前言偏移，不能固定相减；以最终页码标签和目标对象为准。
渲染修改词头所在页、符号索引页、索引首末页，检查分栏、子项缩进、长词换行、
跨页续项和裁切。链接解析/点击、页图检查、正文语义复核应分别记录，不能互相代替。
记录条目数变化及合并理由；“重复一级词头为零”只表示该项检查通过。
构建警告按证据处理：例如 xindy 对罗马页码 `v` 的类型提示，应查实际输出和落点，
不能把它算成致命错误，也不能未经检查宣称无影响。
