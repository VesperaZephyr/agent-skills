# 期末复习讲义工程流程 (跨科目通用)

> 配套规范: `references/lecture_notes_spec.md` (写什么, 怎么写), `references/lecture_notes_pitfalls.md` (出错怎么定位), `assets/lecture_notes_template.tex` (骨架).
> 本文件只讲**怎么把一份讲义从零推进到交付**, 与科目无关. 所有命令中的路径都是示例, 实际路径由项目决定.
> 配套工具均在 `scripts/`, 纯 Python 标准库实现, 不依赖第三方包.

---

## 0. 流程总览

```
题源盘点 → 建台账 → 逐题分类 → 搭骨架 → 分章迭代(备份/片段/合并/编译/验收/回拷)
        → 全书终检 → 交付 + 台账与记忆回写
```

一次只推进一章, 每章交付后再续下一章. 不要一次写完全书再统一验收: 错误会叠在一起, 定位成本成倍上升.

---

## 1. 动笔前的输入清单

动笔前把下列材料凑齐并登记到台账, 缺一项就先补, 不要边写边找:

| 材料 | 用途 | 登记内容 |
| :--- | :--- | :--- |
| 教材或讲义 OCR / 电子版 | 取定义, 定理, 习题原文与页码 | 章节范围, 可用页码 |
| 平时作业 (含解答) | 现成的题目 + 完整解答 | 第几次作业, 覆盖哪些知识点, 是否已有解答 |
| 历年真题与解析 (含回忆版) | 高频考点, 卷面结构, 逐年重复的题型 | 学年学期, A/B 卷, 题号, 是否解析成对; **回忆版的题干数据 (矩阵, 系数, 右端, 初值) 一律记"待核", 经用户确认后才能写入讲义** |
| 教师新布置的作业 (照片 / 板书) | 最新考点 | 可读题号; 涂改或疑似增删处要向用户确认 |
| 考试范围 | 裁剪考纲外内容 | 明确到节, 例如「第三章 §1--§3」 |
| 考试作答语言 | 决定题面与解答的语言 (见 `lecture_notes_spec.md` §3.5) | 母语作答还是英文作答; 双语课程要问清, 不要按"教材语言"推断 |
| 文体正面 / 反面范本 | 校准叙述体 | 项目记忆中的路径 |
| 用户指定的人写讲义 (文风基准) | 校准直陈文体与详略; 加载 `references/lecture_notes_voice.md` | 项目内路径 |
| 复习 beamer (本人或上届编写) | **方法清单与解题技巧** (不只是题目) | 逐条摘出其中的手法, 与本书章节对照, 登记已覆盖 / 缺口 |
| 课堂 PPT (教师课件) | **知识结构与教师强调的易错点** | 单列一份清单: 每页的主题, 画出的知识结构图, 明确写"这里要细致理解"的段落, 课后布置的极限/证明类习题 |

两类参考材料的侧重不同, 必须**分别**登记, 不能合并成一份"参考材料"清单后就地对照:

- beamer 通常由一个学生编写, 主体是"这道题怎么算快", 技巧密度高, 编排随意, 可能跳步;
- 课堂 PPT 由教师编写, 主体是知识结构 (目录, 框图, 各章要点串联) 与教师认为学生容易含糊的少数几处, 计算技巧少但**结构性缺口**多, 例如"由一个解求另一解"这类教材有公式而正文没展开的环节.

只读其中一份, 必然漏掉另一份的整类内容. 本轮实测: 读完 beamer 后补了 6 类技巧, 用户追问"那 PPT 读了吗", 再读 PPT 又发现 9 处缺口 (代换技巧族, 两个抽象函数方程, 降阶公式, 常数变易的行列式一般形式, 特征根实部判据, 自伴系统, 矩阵级数两题, 代数重数与几何重数的对照). 两份材料的覆盖集几乎不重叠.

题面照片识别结果要保留不确定性: 涂改, 双下划线, 行末附加符号都可能是增删标记, 按可读题号登记后向用户确认一次, 不要自行推断.

参考材料的价值主要不在题目, 而在**手法**. 用户自编或往届的 beamer / PPT 常含教材正文没有写明的技巧 (例如用算子恒等式 $D+a=\e^{-at}D\e^{at}$ 把极限问题化归到右端, 用秩一矩阵的恒等式 $\bm B^{2}=\tr(\bm B)\bm B$ 免算矩阵乘法, 用 $y=\varphi+1/v$ 一步跳过 Bernoulli 中转换元). 这些内容不会出现在题号索引里, 只按题目对照就会整类漏掉.

做法: 通读一遍参考材料, 把每一个"这里可以这样做"的句子摘成一行 (手法名 + 一句原理 + 它能替代什么常规做法), 汇总成对照表; 再逐行判断本书是否已有等价陈述. 缺口按"是否落在考纲内"排序, 优先补能直接减少计算量的手法, 而不是补更多例题.

读 `.pptx` 时先跑 `python scripts/extract_pptx.py <课件.pptx> -o _ppt_text.md --media _ppt_media`. 脚本按节点**本地名**匹配 (兼容 PowerPoint 的 `<a:txBody>` 与 WPS 的 `<p:txBody>`), 同段聚合 `a:t` 与 `m:t`, 并把每页引用的图片导出为 `s{页}_{序}.{ext}`. 一般课件的公式与推导都是截图, 文字稿只覆盖目录与结论, 因此文字稿读完还要逐张看导出的图片: 一份 36 页课件常有 40 余张公式截图. 若某页仍无文本也无图片, 多半是 SmartArt 或图表, 在渲染页面上看.

作答语言问晚了的代价是整书返工: 先按中文写完全部解答, 再改成英文, 等于把 60 余个解答重写一遍. 这门课的常见情形是"教材与试卷英文, 讲授中文, 但答题也要求英文", 三者并不一致, 因此必须单独确认.

真题 (尤其是学生的回忆版) 的风险不在"题少了", 而在"题面失真". 矩阵里一个符号就能改掉迹, 特征值, 单值矩阵与全部结论, 而错误数据往往也能算出一个自洽的答案, 因此不能靠"结论是否漂亮"辨别. 做法是: 台账里先标"待核"; 写入讲义前把矩阵或方程原样贴给用户确认; 用户只给方向 ("我记得没那么复杂") 时, 给一两个候选版本让用户挑, 不要自己按推出来的结论改题面; 确认后把讲义, 练习, 手册条目与该题在真题源文件中的正文四处一起改. 本次代价: 一处符号错使结论从"解存在但不唯一"翻成"判据为空, 解唯一", 例题, 练习, 手册与真题源全部返工.

## 2. 第一步: 建题源台账

```bash
python scripts/source_ledger.py init --out "<项目>/题源台账.md" --course "<课程名>"
```

台账至少包含: 题源文件与规模表, 「知识点 → 题号 → 出处 → 是否已有解答」索引, 章节交付状态, 每章已占用题源. 模板见 `assets/source_ledger_template.md`.

登记时给每题打一个处理标签, 后面写正文时直接按标签取用:

| 标签 | 含义 | 对应 LaTeX 环境 |
| :--- | :--- | :--- |
| 结 | 结论型: 判定, 性质, 等价刻画, 结构公式 | `proposition` / `corollary` / `lemma` + `proof` |
| 例 | 计算 / 构造 / 综合型, 需完整解答 | `example` + `solution` |
| 练 | 题干 + 就地紧跟的完整解答 (与例题同规格) | `exercise` + `solution` |

**同一题只在一处作为例题**. 结论型习题融入正文命题并标注出处, 不再重复挂例题 (规范 §2.1 第 6 条). 每章交付后立刻把台账里该章的「预留」改成「已占用」并列出题号, 这是后续章节不撞题的唯一保障.

### 2.1 真题逐题落点表 (确定考试范围后第一件事)

范围一旦拿到, 先给整份真题排一张表, 再决定哪些内容归档:

| 列 | 填什么 |
| :--- | :--- |
| 题号 | 卷别 + 题号 |
| 本题所求 | 一句话: 求通解 / 判定周期解 / 证明极限为零 … |
| 实际用到的结论与手法 | **写到小节与定理号**, 不写"第 X 章" |
| 讲义落点 | 落到哪一节; 若该节还没写, 标"待建" |
| 范围内 | 是 / 否, 并注明"删去某节后这题还做不做得动" |

两条判据:

- 真题的"章"由**解法**决定, 不由教材把它编在哪一章决定. 一道用基解矩阵与伴随系统就能做完的题, 即使教材排在考纲外的一章, 也不依赖那一章的理论, 必须收.
- 只有当"解法里用到的定理全部在范围外"时才归档. 若只有某个结论的推广形式在范围外, 就在范围内重证该结论再收, 不连题一起丢.

同一处失误重复发生过两次 (先丢一阶线性极限题, 再丢连年出现的周期解末题), 原因都是落点表只填了教材章号. 连续两年及以上出现的题型, 按规范 §1 第 6 条独立成节或成章.

## 3. 第二步: 搭骨架

```bash
python scripts/lecture_notes_scaffold.py init --out "<项目>/讲义.tex" \
    --course "<课程名>" --author "<编写者>"
```

`init` 复制 `assets/lecture_notes_template.tex`, 替换占位符, 写成 UTF-8 无 BOM + CRLF. 该模板已含 `aliascnt` + `cleveref`, 盒式定理环境, `solution`, `\takeaway` / `\examtip`, 按节编号公式, 三线表.

篇幅大 (预计 40 页以上) 时按项目需要改用 `ctexbook` 分章, 封面 + 使用说明 + 目录 + 各章 + 手册. 章节名一律是考点或方法名, 目录即考纲. 题目编排在搭骨架阶段就要按规范 §1.1 规划: 先判「同一个题」(题干一致 / 同一实例的不同考察方式) 并合并成一道多问例题, 再把「数据不同但方法相同」的同类题按解题方法分组, 每组对应一个以方法命名的 `\subsection`; 不要先排完知识点再按题号插题, 也不要把同类题合并掉.

## 4. 第三步: 分章迭代 SOP (核心)

每章严格按下面九步走, 顺序不要跳:

1. **备份**: `python scripts/lecture_notes_scaffold.py backup <讲义.tex>`. 保留可回滚点.
2. **片段外置**: 本章正文先写成独立的临时片段文件 (如 `<临时目录>/ch3.tex`), 不在主文件上做大段编辑. 片段同样是 UTF-8 无 BOM + CRLF.
3. **合并**: `python scripts/lecture_notes_scaffold.py add-chapter <讲义.tex> --title "..." --sections "..."`, 或手工把片段插到 `\end{document}` 之前. 后者要确认插入点唯一.
4. **同步封面与元数据**: 加章后改 `pdftitle`, 封面副标题与范围说明, 否则封面与目录不一致. 封面不可与表格内容重复, 也不写编写体例说明.
5. **三轮编译**: `python scripts/lecture_notes_build.py <讲义.tex> --workdir <临时目录> --passes 3 --copy-back`.
   - 首轮出现大量 `undefined reference` 是 `.aux` 未稳定的正常现象, 不要当成错误去改源码; 三轮后再判断.
6. **源码层验收**: `python scripts/lecture_notes_audit.py <讲义.tex> --strict`.
   - 每次追加新章都要**全书重扫**, 不是只扫新章: 元话语, 全角标点, 禁用词常在旧章里残留, 新章的措辞也会污染旧章统计.
   - 正则要兼容 `\begin{exercise}[{...}]` 这种带花括号的可选参数, 否则题源覆盖率与练习解答配对会算错.
7. **PDF 文本与视觉验收**: `build.py` 已做 `pdftotext`; 再渲染抽样页人工看:
   ```bash
   python scripts/lecture_notes_build.py <讲义.tex> --render <章首页>,<含新公式页>,<手册表页>,<练习解答页>
   ```
   抽样页至少四类: 章首页, 新引入公式所在页, 三线表所在页, 练习解答页 (含 exercise 与紧随其后的 solution).
8. **数学复核**: 编译不会检查数学. 逐条复核取值同态, 消去步, 反例是否真满足全部条件, 题号与题面是否对应. 同时对照教材编号表的「有无证明」一列: 教材写了证明而讲义只有陈述的, 补 `proof` 并照教材的论证路径分段; 补完读该段末句, 看有没有被漏掉的「反方向」或附注 (规范 §2.0bis 第 8 条). 这一步只能人工做.
9. **回拷与登记**: 确认 `<临时目录>` 与项目目录的 `.tex` / `.pdf` 哈希一致, 更新台账该章「已占用题源」, 再进入下一章.

### 补题: 按「问法」铺练习, 不是按「题」堆数量

用户说「这一题多设计一些练习」时, 先列问法清单, 再动笔. 同一结论通常有五六种包装, 每种配一道, 才算把题型铺开; 只加同型题会让学生以为只有一种考法.

1. **问法清单只用于选题, 不写进正文**: 按问法挑题, 让题干与解答自己说话. 不在每道练习前加「这一问对应哪种问法」的编者说明, 也不在练习后写「指出陷阱在哪」的收束段 —— 这两类复述是防御感的主要来源 (`lecture_notes_voice.md` §2). 若确需把几道题串成一条线, 用小节导语里的一句数学陈述讲清共同构造, 不逐题点评.
2. **难度梯度**: 直接套判据 → 需要先判判据是否为空 → 判据退化还要算积分 → 只给抽象数据(单值矩阵/乘数) → 参数取特殊值问更细的性质(最小正周期、解是否唯一).
3. **让练习可「逆用」**: 好练习不是「已知 $\bm A$ 求乘数」, 而是「已知乘数问 $\bm A$ 的性质」, 例如只给 $\bm\Phi(\omega)$ 问周期解个数. 这类题考定理的逆用与线性代数细节(代数重数 vs 几何重数), 计算量小, 区分度高.
4. **陷阱题要有干净的数值例**: 例「均值 $\bar p=0$ 但没有周期解」用 $y'+(\cos x)y=1$, 正交积分 $\int_0^{2\pi}\e^{-\sin s}\,ds\geqslant2\pi\e^{-1}>0$ 一句话判死; 比选一个需要精确积分的右端更可靠.
5. **题源标注不能省**: 变式也要写清来路, 如「教材 §2.7 习题 5 的二阶非齐次推广」「只给单值矩阵, 定理 2.7.1 的逆用」. `audit.py` 按 `SOURCE_RE` 检查每道 `example`/`exercise`, 且**相同字符串出现两次会被记为重复出处**; 变式的标注措辞要与原题不同.
6. **每加一题都重算台账**: 该章「例 / 练 / 结」数目按 PDF 实际环境数, 章页范围与全书合计一起改, 否则下次核对必然对不上.
7. **写"恰为""唯一""最小""当且仅当"之前先找反例**: 补变式时最容易把结论说过头. 本次初稿写"最小正周期恰为 $2\omega$", 而 $\cos(3\pi t/\omega)$ 的最小正周期是 $2\omega/3$, 正确说法是"$2\omega$ 是周期, $\omega$ 不是任何非零解的周期, 最小正周期可以是 $2\omega$ 的真因子". 凡带这类限定词的句子, 先构造一个更弱的反例去撞它, 撞不动再落笔; 变式练习本身就在考边界, 断言过强会让整题失效.
8. **合并去重后的补配比要最小充分**: 合并「同一个题」会留下只有例题没有练习的小节, 按规范 §2.1 第 9 条补, 但先删掉挂在 `\section` 直属、不补任何 `\subsection` 配比的题, 以及本就由教材命题承担示范的小节; 新题优先写成已有原题的实例 / 变式, 短显示公式改行内. 每加一题重新统计全文行数与页数并做分阶段对照编译 (见 `lecture_notes_pitfalls.md` §13), 别把「题块减少」当成「页数一定减少」.

## 5. 第四步: 三层验收, 各管各的错误

| 层 | 工具 | 能抓到 | 抓不到 |
| :--- | :--- | :--- | :--- |
| 源码层 | `lecture_notes_audit.py` | 例解配对, label 重复 / 未定义引用, 题源标注覆盖与撞题, 练习解答配对与禁提示段, 禁用词, 全角标点, 斜杠错字, 公式 `\label` 位置, 提示框参数个数, BOM / 行尾 | 编译错误, 断行, 引号方向, `\cref` 实际类型名, 公式渲染 |
| 编译日志层 | `lecture_notes_build.py` | `! ` 错误, LaTeX / Package Warning, 未定义引用, Overfull / Underfull hbox, Missing character, 页数 | 语义错误, 字面斜杠命令, 引用类型名串位, 表格拆行 |
| 视觉层 | `pdftotext` + `pdftoppm` 渲染抽样 | `??`, 字面斜杠文本, `\cref` 类型名 (定义 / 定理 / 命题 / 例 / 练习 / 式), 中文引号方向, 表格与练习解答截断, 盒内容溢出 | 数学内容是否正确 |
| 语言层 (要求英文作答时) | 一次性脚本扫 `solution` 块 | 块内 CJK 与全角标点计数, 块内 `\cref` 计数, 题面 (`example` / `exercise` 体) 含 CJK 的个数; 三者都应为 0 | 译法是否地道, 术语是否统一 |
| 文体层 (人工) | 按 `lecture_notes_voice.md` §9 连读一章 | 方法论章导语, 末尾编者复述 / 复验, 提醒框复述前提, 证明首段在铺垫, 元话语总起句 | 编译错误, 数学错误, 词面禁用词 |

**只有第三层能发现的错误最容易被漏掉**, 而它们恰恰不产生任何编译警告. 交付前必须做, 不能因为「日志 0 error / 0 warning」就跳过. 语言层的四项计数都是 0, 也不等于英文写得对: 术语要在全书中保持一致 (例如 "general solution", "fundamental system of solutions", "integrating factor" 各只用一种译法), 这一项只能人工通读. 文体层同理: `audit.py` 全绿只覆盖词面与结构, 直陈与否必须连读一章, 不计入三层工具验收.

## 6. 第五步: 交付与记忆回写

交付物: 讲义 `.tex` 与 `.pdf` (两者哈希与构建目录一致), 必要时附题源台账.

每完成一章, 把下列四处同步更新, 否则下次续写会重复劳动或撞题:

| 位置 | 写什么 |
| :--- | :--- |
| 项目日志 `.workbuddy/memory/YYYY-MM-DD.md` | 本章交付内容, 规模, 编译结论, 修正明细 (追加式, 不覆盖) |
| 项目长期记忆 `MEMORY.md` | 复用的版式约定, 新踩的 LaTeX 坑, 当前进度 |
| 用户级长期记忆 `MEMORY.md` | 跨项目可复用的工具经验 (如新发现的 XeLaTeX 陷阱) |
| 技能规范 `references/lecture_notes_spec.md` / `pitfalls.md` | 只有**与科目无关**的经验才回写; 课程专有事实留在项目记忆 |

写记忆时两点纪律: 追加函数要允许目标文件不存在 (否则 `FileNotFoundError` 会打断收尾); 写含反斜杠的 LaTeX 内容时, 用文件写入工具生成 UTF-8 文本再字节级追加, 别把反斜杠塞进 shell heredoc, 写完用另一个工具独立回读确认.

## 7. 常见失败模式

| 症状 | 原因 | 处理 |
| :--- | :--- | :--- |
| 加章后旧章冒出禁用词 / 顿号 | 全书重扫时把旧章遗留一起算进来了 | 全书一次性清理, 不要只改新章 |
| 同一道题出现两次 | 台账没及时标「已占用」 | 保留一处作 `example`, 另一处改成 `\cref` 指向 |
| 练习缺完整解答 | 只在 exercise 后留题干, 或把答案 / 提示集中到章末 | `audit.py` 逐题检查 exercise 后是否紧跟 solution, 并把任何练习提示段判为 ERROR |
| 题源覆盖率算成 0 | 正则没兼容 `[{...}]` | 用带花括号的可选参数解析 |
| 首轮上百条 undefined | `.aux` 未稳定 | 连续编译三轮后再判断 |
| Overfull 十几 pt | 长行内公式与中文挤在一行 | 抽成显示公式 |
| Underfull 来自手册表 | `\mbox{\cref{...}}` 把引用锁成一行 | 调 `tabularx` 的 `\hsize` 比例 |
| PDF 里公式成了字面 `/Q`, `/infty` | 源码反斜杠误写成斜杠 | 源码正则扫描 + 渲染抽样, 编译层无感 |
| 批量替换后内容没变 | shell 把替换串里的反斜杠改写, `str.replace` 静默 no-op | 用 `chr(92)` 构造反斜杠, 并用独立工具回读文件 |
| 封面写「群论」而目录有三章 | 加章后没同步 `pdftitle` / 副标题 | 每章合并后统一改封面 |
| 真题按回忆版数据算出的结论与题面难度不符, 或算到一半卡住 | 题面转抄时错了一个符号, 错误数据也能算出自洽答案 | 不要改题面去凑答案, 把矩阵或方程原样贴给用户确认; 确认后同步讲义与真题源 |
| 范围收紧后, 真题里有题无人讲 | 按教材章号判范围 | 范围到手先做 §2.1 的落点表, 按解法判归属 |
| 复盘改造后出现未定义引用 | 按 label 搬走环境时, 某个 `\cref` 还指向被删掉或被合并的标签 | 结构层结束立刻扫 `refs - labels`, 逐条改指或删除 |
| 正文里出现教材没有的概念 | 为了省事用了别的书里的命名或工具 | 先查教材原文确认, 再连同依赖它的整段解答一起重写; 命名只放进 `remark` |
| 真题只标卷别, 有些标了教材有些没标 | 题源标注只做了第一轮, 补题时没同步 | `audit.py` 的 `exam-source` 检查码逐个列出, 有原题补题号, 无原题补概念锚点 |
| 新写的长显示公式顶出 Overfull | 一行塞进整条展开式 | 拆成两行或用 `aligned`, 别压缩字号 |
| 编译日志报成功, PDF 却是旧版 | 中文文件名被 XeLaTeX 写成 mojibake 文件, 或目标 PDF 被预览器锁定 | 用 `build.py --workdir <临时目录> --copy-back` (构建目录固定 ASCII 名); 回拷被占用时自动另存 `*_终稿.pdf`; 交付前 `pdfinfo` 核对页数 |
| 删了一批重复题, 页数反而涨了 | 补配比新增的独立题带题干盒与完整解答, 比删掉的重复题干长得多 | 分阶段对照编译归因并列阶段表; 别把锅甩给 `breakable` |
| 合并时把数据不同的同类题也并成一道多问题 | 拿「方法相同」当合并判据 | 按规范 §1.1 前置判据分两类, 同类题只聚拢 + 抽公共框架, 见 `lecture_notes_revision.md` §2bis |

## 7bis. 既有讲义的复盘改造 (交付后的结构性反馈)

新建讲义按 §4 分章迭代; 用户拿到成稿后提出「同类型题没放一块 (违反规范 §1.1) / 同一个题写了好几遍 / 排序像按题号 / 名词没标出 / 出现课本上没有的内容 / 真题源自课本却没标来源 / 想补同方法的练习」时, 改走 `references/lecture_notes_revision.md`, **不要重写全文** (这是对成稿要求的事后补救, 不是要求本身). 六类反馈, 五步摘要:

1. **备份用户改动版**到 `.workbuddy/backup/`; 用户自行增删的内容不得被批量脚本覆盖.
2. **三项盘点**: 结构清单 (节与行号), 环境标题清单 (题源标注), 规模清单 (环境与 label 计数); 同时把教材 OCR 抽成习题表并统计争议术语出现次数 —— 判「课本外」必须查教材原文, 不能凭印象.
3. **分三层改**: 文本层 (术语加粗, 课本外术语连同解答重写, 标题补题源) → 结构层 (按 label 把「题目 + 解答」整块搬到新方法小节, 并补同方法变式练习) → 收尾层 (未定义引用, 措辞, 断行). 每层跑一次静态验收; 脚本骨架见该文档 §3. 若反馈是「同一个题写了多遍」, 改走该文档 §2bis 的六步删块合并流程, 先按前置判据分清同一个题与同类题, 别把同类题也合并掉.
4. **四层验收**: `audit.py --strict` (含新增的 `exam-source` / `term-bold` 两个检查码) → `build.py --passes 3` → `pdftotext` + 渲染**新方法小节所在页** (不是只抽章首页) → 人工复核新写解答的每一步.
5. **四处回写**: 台账加「重排记录」并修正过时口径, 项目日志, 项目 `MEMORY.md`, 技能侧只回写与科目无关的规则.

两个新检查码都是 WARN, 确需人工放行时用 `--ignore exam-source` / `--ignore term-bold`, 问题仍完整列在报告中.

## 8. 工具链速查

```bash
# 1 建台账
python scripts/source_ledger.py init --out "<项目>/题源台账.md" --course "<课程名>"

# 2 新建讲义骨架
python scripts/lecture_notes_scaffold.py init --out "<项目>/讲义.tex" --course "<课程名>"

# 3 每章迭代
python scripts/lecture_notes_scaffold.py backup "<项目>/讲义.tex"
python scripts/lecture_notes_scaffold.py add-chapter "<项目>/讲义.tex" --title "<章名>" --sections "<节1>,<节2>"
python scripts/lecture_notes_build.py "<项目>/讲义.tex" --passes 3 --copy-back --render 1,20,40
python scripts/lecture_notes_audit.py "<项目>/讲义.tex" --strict

# 4 题源查重与覆盖
python scripts/source_ledger.py scan "<项目>/讲义.tex" --json "<项目>/sources.json"

# 5 只做静态验收 (无需 TeX 环境)
python scripts/lecture_notes_audit.py "<项目>/讲义.tex" --json "<项目>/audit.json"
```

工具缺省只读源码, 除 `build.py --copy-back` 与 `scaffold.py add-chapter` / `backup` 外不改动原文件; 所有写操作前自动备份.

两个常用开关:
- `audit.py --strict` 会把 WARN 也判为失败. `source-duplicate` 首先当作「同一个题写了两遍」的机器信号: 逐条对到人工聚类, 能合并的合并成一道多问例题. 确属同一真题的不同小问 (例如卷第二题的 (1)(2) 问分别作例题) 才用 `--ignore source-duplicate` 放行, 被放行的问题仍完整列在报告中; **合并去重后该检查码应归零, 归零后不要再放行**.
- `build.py --strict` 只把 error / hbox / 缺字符判为硬失败, 首轮 `.aux` 未稳定产生的 warning 与 undefined 不算失败; 最终一轮仍要求全 0.

`source_ledger.py scan --strict` 在存在未标注题目或两道及以上 `example` 共用出处时返回非零, 适合在题源台账定稿前做一次强校验; 日常扫描不加 `--strict` 即可.
