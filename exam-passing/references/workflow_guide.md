# exam-passing 通用助教工作流与执行规范指南

本指南定义 `exam-passing` 技能在处理课件解析、平时作业、复习讲义与模拟卷命制时的四大标准流水线。四条流水线均为**科目中立**：课程名称、教材、考纲、题型结构与题源一律由当前项目提供，技能内不内置任何课程的教材索引或题库。

---

## 工作流一：PPTX 课件读取与考点萃取 (PPTX Parser Workflow)

### 1. 触发场景
- 用户上传了教师上课的 PPTX 课件，要求“总结课件内容”、“提炼重点结论”、“对照教材查找 PPT 补充考点”。

### 2. 执行流程
1. **执行抽取脚本** (文本与大纲用 Markdown, 公式截图同时导出):
   ```bash
   python scripts/extract_pptx.py <课件路径.pptx> -o <输出.md> --media <图片目录>
   ```
   输出的每页末尾会列出该页图片文件名 (`s{页}_{序}.{ext}`)。课件的推导多做成图片, 文字稿只给目录与结论, 因此须逐张读图, 不能只读文本。
2. **知识点归纳与三级映射**：
   - **概念层**：提取幻灯片核心定义、定理、背景问题。
   - **方法层**：提炼幻灯片中的推导链条、公式、判据以及结论的适用条件。
   - **考点标记**：对照当前项目提供的教材 / 考纲 / 题源台账，标注“教材重点”、“课件补充”、“课后思考题”；技能不内置任何教材考点索引。

## 工作流二：平时作业规范解答与 LaTeX 排版 (Homework Solver Workflow)

### 1. 触发场景
- 用户提出：“帮我写一下第 X 章习题第 Y 题”、“完成这周的作业解答”。

### 2. 解答质量红线（科目中立五环节）
1. **一、题目复述与已知条件**：
   - 不照抄大段背景，用简练的数学语言写清已知量、求解目标与所依附的定义 / 定理。
2. **二、前提与符号约定**：
   - 列明本题用到的假设、适用条件、边界与退化情形；符号较多时必须用三线表（`booktabs`）统一定义, 含符号、含义、变量类型、单位或取值范围。
3. **三、逐步推导与证明**：
   - 每一步写出所依据的定义、定理或公式, 定理带条件, 不跳步；公式居中并按需编号, 引用前文时用 `\eqref` / `\cref`。
4. **四、求解与计算**：
   - 优先给出完整解析推导；课程确需数值计算时, 提供高可读性的代码脚本 (语言按课程约定) 与数值输出。
5. **五、结果检验与讨论**：
   - 用特例、边界情形、量纲或数值复核检验结论, 说明适用范围与失效情形；需要时讨论关键参数变化对结果的影响。

### 3. LaTeX 交付规范
- 基于 `assets/homework_template.tex`（科目中立）模板填充。
- 题面可由 `scripts/homework_helper.py --textbook <教材OCR.md> search <章> <题>` 检索；未指定教材时由用户给出题面, 不假定任何教材文件。
- 行尾保持 CRLF，UTF-8 无 BOM，统一使用英文标点符号。
- 中文叙述按 `references/writing_craft.md` 核句群承接、搭配与逐命题限定；该方法的标点建议不覆盖本技能的半角标点红线。

## 工作流三：期末复习讲义体系化编写 (Review Notes Workflow)

> **本工作流为跨科目通用标准**，适用于任意课程。执行前必须先阅读 `references/lecture_notes_spec.md`，以该规范为准；本节仅给出流水线摘要。

### 1. 触发场景
- 用户提出：“帮我写一份第 X 章复习讲义”、“总结某门课的考点”、“给某门课写期末复习讲义”、“做一份考前公式手册”。

### 2. 执行流水线
1. **加载规范**：阅读 `references/lecture_notes_spec.md`（结构、内容、语言风格、版式、科目适配、验收清单）；句子怎样写顺读 `references/writing_craft.md`，二者冲突时以规范红线为准。
2. **搭骨架**：章节以考点/方法命名，目录即考纲；按方法递进穷举典型情形；末章设「必背公式与结论手册」，按「适用条件—公式/结论」编排（该章名对期末复习有实际作用，予以保留）。
3. **填内容**：每节从本学科机理推导概念与结论（讲清符号、前提、失效情形）→ 方法固化为编号步骤 → 标注来源的教材原题配**逐步完整解答**（一个 `example` 必配一个 `solution`）→ 定理带条件与证明、建立 `\label`/`\eqref` 交叉引用 → `\takeaway`/`\examtip` 只讲数学结构与前提。 题目编排遵守规范 §1.1: 题干一致或同一实例的不同考察方式属「同一个题」, 先合并成一道多问例题; 数据不同但方法相同的「同类题」再按解题方法分组, 编在同一个以方法命名的小节并配变式练习 (含完整解答), 不按题号或年份铺开; 两类动作不冲突, 这是编写阶段就要执行的要求.
4. **守语言红线**：数学书式叙述体；禁元话语（编写体例、勘误、自编标签）、禁考试管理语言（记忆要点、易错点、建议、时间分配、审题技巧、避坑指南）、禁「标签+公式」电报体；前提融入叙述，半角标点，`\boxed{}` 与表格克制。禁用词表与改写示范见规范第 3 节。
5. **套模板并验收**：基于 `assets/lecture_notes_template.tex` 生成 `.tex`（CRLF、无 BOM、XeLaTeX 多轮编译），再按规范第 6 节清单逐项自检。

### 3. 分章迭代与工具链 (跨科目通用)

一次只推进一章。完整 SOP、输入清单、三层验收职责与常见失败模式见 `references/lecture_notes_workflow.md`；排错速查见 `references/lecture_notes_pitfalls.md`。四个脚本均在 `scripts/`，只需 Python 标准库（编译 / 渲染另需 TeX 工具链与 poppler）：

```bash
# 动笔前: 建题源台账, 逐题打 结 / 例 / 练 标签
python scripts/source_ledger.py init --out "<项目>/题源台账.md" --course "<课程名>"

# 新建讲义骨架
python scripts/lecture_notes_scaffold.py init --out "<项目>/讲义.tex" --course "<课程名>"

# 每章: 备份 -> 追加章骨架或合并片段 -> 同步封面 -> 编译 -> 验收 -> 回拷
python scripts/lecture_notes_scaffold.py backup "<项目>/讲义.tex"
python scripts/lecture_notes_scaffold.py add-chapter "<项目>/讲义.tex" --title "<章名>" --sections "<节1>,<节2>"
python scripts/lecture_notes_build.py "<项目>/讲义.tex" --passes 3 --copy-back --render <章首页>,<含新公式页>,<手册表页>,<练习解答页>
python scripts/lecture_notes_audit.py "<项目>/讲义.tex" --strict
python scripts/source_ledger.py scan "<项目>/讲义.tex"
```

三层验收缺一不可：源码层抓例解配对 / 引用 / 题源 / 禁用词 / 斜杠错字；编译日志层抓 error / warning / undefined / hbox / 缺字符；视觉层（`pdftotext` + 渲染抽样）抓 `??`、字面斜杠文本、`\cref` 类型名串位、中文引号方向、表格与提示截断。**日志 0 error / 0 warning 不等于讲义合格**。`audit.py --strict` 的 `source-duplicate` 首先当作「同一个题写了两遍」的机器信号，逐条对到人工聚类并合并；确属同一真题不同小问才用 `--ignore source-duplicate` 放行并保留报告记录，去重后该检查码应归零且不再放行。

> 三层工具验收之外，按 `references/writing_craft.md` §5 对本章正文另做一次连续试读：只按成稿从前读到后，标出读者第一次需要停下来猜对象、用途、理由或前提的位置；承重解释缺失回到章草图补写，不靠加连接词或泛化提示补救。工具查的是词面、结构与编译，查不出读者接不上。

### 4. 交付后的复盘改造 (跨科目通用)

> 本节是**事后补救**: 成稿未达到 `lecture_notes_spec.md` §1.1 等要求 (含同一个题未合并) 时才走复盘流程. 要求本身一律以规范为准, 不在本文件也不在 `lecture_notes_revision.md` 中定义.

用户拿到成稿后反馈「同类型题没放一块 / 排序按题号 / 名词没标出 / 出现课本外概念 / 真题未标教材来源 / 想补同方法练习」时，按 `references/lecture_notes_revision.md` 执行：备份用户改动版 → 三项盘点（结构、环境标题、规模清单 + 教材习题表与术语计数）→ 文本层 / 结构层 / 收尾层三层改造（按 `\label` 搬「题目 + 解答」整块，脚本骨架见该文档 §3）→ 四层验收（渲染抽样页要换成新方法小节所在页）→ 台账、日志、项目记忆、技能四处回写。`audit.py` 的 `exam-source`（真题只标卷别未标教材）与 `term-bold`（definition 术语未加粗）会把这两类遗漏逐条列出；确需人工放行时用 `--ignore exam-source` / `--ignore term-bold`。

> 旧版「知识图谱 + 审题突破口 + Pitfalls Table 易错陷阱」的清单式架构已废止，不得再作为编写依据。

## 工作流四：期末模拟卷设计与评分标准命制 (Mock Exam Workflow)

### 1. 触发场景
- 用户提出：“出一份期末模拟卷”、“设计一套期末考题带答案和评分标准”。

### 2. 卷面参数与双向细目表
- **先确认参数**：考试范围、题型、题量、分值、时长、允许携带的资料（是否可查表 / 用计算器）、往年真题。技能不预设任何科目的题型比例或题目内容。
- **编制双向细目表**：按「知识点 × 题型 × 分值 × 难度」逐题落点，先定覆盖面与分值结构，再动笔命题；回忆版真题的题干数据须经用户确认后才能写入。
- **卷面排版**：基于 `assets/mock_exam_template.tex`（科目中立的空白卷面骨架）填充，题型名称、题量与分值一律按确认结果改写。

### 3. 配套参考答案与评分细则
- 必须逐题给出每一步的得分点（如：写出所用定理 3 分、建立方程 5 分、推导 7 分、结论与检验 5 分），并写明所依据的定义、定理或公式。
- 答案与试卷使用同一套题源，交付前核对各题分值合计与双向细目表一致。
- 题干与参考答案的中文表述按 `references/writing_craft.md` 校对：条件与结论同句可核、数值写明对象与单位、回指唯一、无伪承接；评分细则每一步的得分点写成可核对的动作，不写泛化提醒。
