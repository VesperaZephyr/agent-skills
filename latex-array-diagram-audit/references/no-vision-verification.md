# 无法直接识图时，如何核验交换图

## 确定限制，避免把工具故障当成模型结论

先用现有本地文件测试当前图片显示/查看工具，检查是否实际收到可读图像。路径错误、格式不支持、工具拒绝或过滤信息，都可能导致失败，不等于模型一定是纯文本模型。更换受支持格式或修复路径后重试一次；仍无法直接检查图像时，按“本轮未直接目视核验”记录，继续下面的工作。不要用 OCR 文字输出冒充视觉输入。

## 源码结构检查不依赖识图

1. 列出整个实际编译链的图候选。检查每个 `array/aligned/matrix` 内的横/竖/斜箭头或包含线；箭头放在 `\overset`、邻接环境或自定义宏中时也纳入。只审 `tikzcd` 会系统性漏掉旧图。
2. 展开节点网格：只在顶层切分 `&` 与 `\\`，保留空节点；注意 `{...}` 内的子矩阵、`\&`、`ampersand replacement` 和换行附加距离，不要简单字符串切分。
3. 建立译图有向边表。核对当前节点、`r/l/u/d` 的行列位移、`from/to`、命名节点，合并本地选项及实际生效的全局/宏样式。记录箭头头所在端与钩所在端；`\arrow[r,leftarrow]` 不是从左向右的普通映射，`hook'` 不是反向箭头。
4. 独立建立原图的边表；证据优先是与出版版相符的原始 TeX，或能够明确还原箭头的原 PDF 几何/字形信息。检查每条边的数学定义域/值域与证明，作为一致性检查。**若只有译稿，不能拿它来生成“原图真值”。**

原图边表可用下列字段：

```json
{
  "diagram_id": "II.3-diagram-2",
  "source_pdf_page": null,
  "translated_file_line": null,
  "edge": {
    "from_node": "A", "to_node": "B",
    "head_at": "B", "tail_at": "A", "tail_style": "hook",
    "label": "i", "line_style": "solid"
  },
  "source_evidence": null,
  "source_relation_status": "unresolved",
  "rendered_style_status": "unresolved",
  "visual_inspection": false
}
```

补全真实位置和证据后才能改变状态。字段为空就是待核对，不能由“预期应当单射”自动改成已确认。

## PDF 几何核验能做什么、不能做什么

对于有文字层和矢量内容的 PDF，限定到确认的图裁剪框，导出 `page.get_text("rawdict")` 的文字/字形位置、`page.get_drawings()` 的路径/填充及图像对象信息。先做坐标系归一化，处理旋转、变换和裁剪；分别记下物理页及矩形。页中其他下划线、表格边框和公式分数线不是图中的边。

将节点位置与长线段/曲线结合，定位边的两端，再查看端部的小斜线、填充三角、弯钩、双头间距。箭头头和钩也可能是数学字体字形、复合路径、PDF XObject 或扫描图像，而不是两条短线；文字提取/OCR 经常只保留长杆或标签。**没提取到箭头头不证明它不存在，`get_drawings()` 路径条数也不能直接当箭头数量。**

同样，不要因为原图仅提取到普通连线，就把译稿向上箭头判为正确。无头线与有向映射不同。若已经有充分证据确定原图无头，译稿用 `dash` 或适当无头样式；证据不充分则标为未决。

可自动确认的是有证据支持的几何事实：例如某端附近确有一组可追溯到该边的箭头头笔画；某边两端和节点坐标匹配；译稿端部有钩路径且没有被裁剪。阈值依字体、比例、线宽校准；重叠边/曲线交叉/字形无法解码时，不猜。原图与译图不要求像素一致，但节点连接和箭头类型必须对应。

## 原图只有扫描图或微细部位仍不能判断

- OCR 用来找页和节点文字；只有明确支持箭头形态识别且经过样例验证的工具输出，才能作为形态证据。普通 OCR 的 `→` 输出不足以排除原书的 `↪` 或双头。
- 若现有环境有支持图像输入的工具/模型且使用在授权范围内，交付原/译图裁剪和逐边问题，要求回答端点、头/钩及不确定项；确认工具真的收到图像，不能让另一个纯文本模型读 OCR 后声称看图。
- 没有这样的能力时，仍完成候选分类、源码纠错、编译、原/译裁剪、图编号/原书页映射、边清单及能证明的 PDF 几何检查。无法确认的方向/钩/遮挡列出具体图、边、文件行及裁剪位置；必要时只请用户核对这些最小问题，避免笼统要求整本书截图。
- 用户确认或可靠证据到达后，才完成依赖它的修补。别因缺视觉直接放弃可做工作，也别为了“完成”编造最终视觉通过。

## 绘制时减少失误，但不混淆证据等级

用 `tikzcd` 及明确的端点/`hook`/`two heads`/`equal`，去掉覆盖端部的自定义默认样式。常见钩丢失小样：

```latex
% 后面的 rightarrow 会重置端部；不要把“源码含 hook”当作验收。
\begin{tikzcd}
  A \arrow[r, hook, rightarrow] & B
\end{tikzcd}

% 只有原书已确认这条边为单射，才采用这个修复。
\begin{tikzcd}
  A \arrow[r, hook, "i"] & B
\end{tikzcd}
```

单独编译小样检查样式，随后在整本书中重编译，排除全局样式、短箭头、标签盒、线宽、行列间距或裁剪使钩不可见。换 `hook'` 只改变钩侧别；若需反向，修正源/目标节点及方向，并检查钩还在真正源端。

“已核实原书拓扑”“已核实译稿源码”“已核实输出路径”“已直接看图”是不同结论，分别记录。纯文本模型可以完成有充分文字/几何证据的结构检查；在缺少原图形态证据时，不能给出完整视觉保真结论。
