# 交换图审阅：覆盖、修复、最终页闭合

本流程用于连续审阅和整书终审；单图任务使用同样的证据标准，不必建立整书工程。
微观图形陷阱见[连续审阅](continuous-review.md)，命令及输入格式见[工具说明](reusable-tools.md)。

## 1. 明确范围和版本

- 以出版版PDF的可见内容为准。记录原书身份和哈希，原始TeX/OCR仅辅助定位；疑似源书错误另列，不静默纠正。
- 从实际构建链盘点候选，并从原书独立盘点实际图。两份清单对应起来，才能发现原书有而译稿整幅漏掉的图。环境/箭头命中数不是图数，不能用相同数量证明对应正确。
- 分类：态射图/元素追踪/复形或正合列、普通公式矩阵或表格、普通几何图、宏待展开、未决。包括环境外和被调用宏，不强制迁移普通矩阵。
- 构建退出后冻结PDF，代理和裁图只读取冻结副本；不要把仍在写入、页数暂时截短的main.pdf交给审阅者。冻结工具检测复制期间变化，不能证明一个暂停的写入进程以后不会恢复，故它不替代等待构建退出。

## 2. 按图建台账，独立列两份边表

每图用稳定ID标识，行号仅作定位提示。重复出现的同名对象按出现位置编号；源字符串哈希、临近陈述/文字、图中节点共同确认身份，不能仅按旧行号回填。

建议一个项目台账保存如下字段；采用项目现有等价格式即可，不要求机械转为此JSON：

```json
{
  "id": "ch9.mapping-cone.shifted-grid",
  "classification": "diagram",
  "source": {"pdf_sha256": "...", "page": 687, "evidence": ["source-full.png", "source-detail.png"]},
  "target": {"tex": "chapters/ch9.tex", "snippet_sha256": "...", "pdf_sha256": "...", "page": 614},
  "edge_review": "done",
  "repair": "applied",
  "final_review": {"method": "direct_visual", "pdf_sha256": "...", "evidence": ["target-full.png", "target-detail.png"]},
  "unresolved": [{"edge": "e7", "property": "stroke", "reason": "source scan cannot resolve dash pattern"}]
}
```

实际台账应区分：候选已分类、源译逐边已核、修复待应用/已应用、最终页待验/直接目视/图面一致沿用、具体未决。整页已打开也应记录；文件导出不自动算看过。不要用一列“完成”吞掉这些区别。

先从原书恢复节点/边，再看冻结译稿的实现；核对两份清单的节点出现位置、端点、方向、头/尾/杆、标签的完整TeX结构及逻辑力度。尤其复查上下标、滤过标记、负号、复合、0/id/+1、问号和存在/唯一性；图轮廓正确仍可能漏掉所有节点的同一个小下标。

## 3. 整图定位后放大，修复前先收齐本批缺陷

- 实际打开两版整页，用图前后文字确认身份，再从原PDF重渲染完整局部。裁框应含全部面板、上下续接、远端弧线和标签。发现裁切不全即废弃其完整性结论，扩框重取。
- dpi由待查细节和源质量决定。低清扫描放大到600dpi不产生新信息；高dpi文件也可能因展示缩放而看不清，应缩小裁框分区，保持整图概览。
- 一批源图先核完，收齐精确替换计划并预检，再合稿构建；不要在每发现一根边时启动整书构建。进入最终页回归后若发现真实新缺陷，仍须修复并重验，不能为“收尾”跳过。
- 对几何重排、三角展开为移位序列、正文标签显化等，按用户保真要求裁定并逐边记录对应；不能将数学等价默认写成印刷完全一致。为可读性改变路由须保留内容并披露差异。

## 4. 合稿和构建是单写者任务

代理只写独占证据/边表/精确提案；主持者负责共享源文件、生成器、构建和最终版本。干净上下文且先源后译才能称独立审阅；继承上下文的检查称续审或回归。

每次提案绑定目标文件字节哈希、old/new/expected_count；哈希过期时回到当前上下文核对，不能只换哈希强行应用。用精确替换工具预检、备份、串行应用；保留原BOM/行尾。生成器工程改生成器再生成，直接维护TeX的项目改其真实源文件。

复杂图先用实际宏/样式编译小样并打开；确认列距和路径的改动确实生效。然后按项目原构建流程构建整书，检查真实退出码、最终日志、索引/引用收敛、缺字和新增溢出；中间pass吞错或包装器打印“完成”不代表成功。

## 5. 先前目视结论怎样转移到最终PDF

- 最终文件变化后，旧通过记录仍属于旧哈希。若页数相同且确定未重排，可明确使用相同物理页对；有分页漂移则先独立定位，给出显式映射。
- 相同页数不保证页码对应。文字相似、OCR相同或相同页眉只能帮助定位；自动相似度/贪心配对可能把同一新页用多次、遗漏新增页，不能直接授予通过。
- 对已实际看过、范围完整且页对确认的图，渲染像素一致可记录“图面一致，沿用旧版目视结论”，注明旧/新哈希、DPI和比较记录；这不是新的独立审阅或对原书的自动认证。
- 对变化页、新增页、无法一对一对应的分拆/合并页，打开新整页重新定位、重取局部；旧裁框即使还包含一幅图，也可能已经变成另一幅图。不要仅沿用文件名。
- 变化页中的邻图也需检查。缩小全图、调标签、添下标可能改变段落和分页；无overfull不能排除局部压字。

## 6. 完成判据与交接

按稳定图ID逐项汇总，不能把“分派38幅”“修了15幅”“打开整段页图”升级为38幅逐边通过。中断时列出下一未审图；只剩细线未决时也逐项列出，不把未审范围改名为“源书不清”。

交付报告绑定最后成功PDF哈希、页数、构建日志和逐图验收。没有待审范围、待合稿修复或待最终页验收，才可说本次审阅完成；若还有源图信息限制，可报告“审阅完成，保留以下具体未决”，不能说所有方向/钩/线型无疑。集中维护未决列表，并合并早期台账，避免总报告漏掉较早发现的限制。
